## 1. 产品概述

### 1.1 产品定位

**DoForMe (任务圈/共识集市)** 是一个基于地理位置与社交关系的去中心化任务协作与轻量级价值交换平台。

**核心理念**: "任何互助都能被量化、流转、兑付"

### 1.2 一句话描述

用户可以像发朋友圈一样发布任务，像使用多币种钱包一样管理信用资产，用自己发行的"个人货币"或团体币奖励他人，构建独特的社交价值网络。

### 1.3 核心价值主张

**对C端用户**:
- 让微小劳务(取快递、问问题、陪逛街)立即获得可量化的信用凭证
- 这些凭证可在社交圈内流通和兑换

**对小团体(家庭/社团)**:
- 快速建立内部经济系统
- 通过任务-奖励机制降低管理成本
- 可视化贡献度和债务关系

**对平台**:
- 成为去中心化劳务的结算层
- 通过交易手续费和世界币充值盈利
- 构建新型社交价值网络

### 1.4 技术栈

- **开发语言**: ArkTS (TypeScript的超集)
- **UI框架**: HarmonyOS ArkUI
- **开发工具**: DevEco Studio
- **目标平台**: HarmonyOS 4.0+

## 2. 三层货币体系

平台采用**三层货币模型**，严格区分流通范围与价值锚定：

### 2.1 货币体系总览

| 层级 | 名称 | 发行方 | 价值锚定 | 流通范围 | 合规定位 |
|------|------|--------|----------|----------|----------|
| **L1 通用层** | **世界币 (Shell)** 💎 | 平台官方 | 人民币 (1:1) | 全平台 | 预付积分，可充值提现 |
| **L2 社交层** | **个人币 (Star)** 👤 | 每个用户 | 个人信用与劳务承诺 | 朋友网络 | 债权凭证，不可法币化 |
| **L3 组织层** | **团体币 (Guild)** 👥 | 团体管理员 | 团体内部共识 | 团体内 | 内部积分，管理员兑付 |

### 2.2 货币详细说明

#### 世界币 (Shell) 💎

**特点**:
- 平台官方发行，硬通货
- 1:1锚定人民币
- 全平台通用
- 可充值、可提现(收20%手续费)

**获取方式**:
- 人民币充值(1:1)
- 完成世界币任务
- P2P交易

**使用场景**:
- LBS探店任务
- 陌生人任务交易
- 跨团体结算
- 提现通道

**风控机制**:
- 充值上限: 单用户5000元
- 提现重税: 20%(鼓励内部流通)
- 任务强制托管: 防止发布者跑单
- 新用户保护: 24小时内不能发布世界币任务

#### 个人币 (Star) 👤

**特点**:
- 用户注册时自动创建
- 命名规则: "[昵称]币"
- 可无限增发，无成本
- 价值由发行者信用背书

**获取方式**:
- 完成个人币任务
- 接受他人转账
- 发行者增发

**使用场景**:
- 朋友互助
- P2P任务协作
- 人情债量化

**风控机制**:
- 单次赏金限制: 不超过历史发行量的10%
- 增发记录公开: 供市场参考
- 不可主动"出售": 防止证券化
- 社交差评机制: 争议时曝光

#### 团体币 (Guild) 👥

**特点**:
- 团体管理员独享铸币权
- 可无限增发
- 团体内封闭流通
- 管理员线下履约

**获取方式**:
- 完成团体任务
- 管理员分发
- 团体成员转账

**使用场景**:
- 家庭教育激励
- 社团协作管理
- 组织内部激励
- 成员贡献度管理

**风控机制**:
- 通胀预警: M2增速超过储备增速时警告
- 退出机制: 成员退团时可兑换/转让/作废
- 国库可视化: 铸币总量 vs 已兑付量
- 管理员权限控制

## 3. 核心应用场景

### 3.1 场景映射矩阵

| 场景 | 货币类型 | 核心角色 | 信用基础 | 验证方式 | 关键机制 |
|------|----------|----------|----------|----------|----------|
| **朋友互助** | 个人币 (L2) | 双边好友 | 双边熟人信用 | 手动确认 | 1对1指派，可协商，债务清算 |
| **家庭教育** | 团体币 (L3) | 家长 vs 孩子 | 家长权威 | 家长验收 | 家长铸币，任务派发，家庭商店 |
| **社团协作** | 团体币 (L3) | 社长 vs 社员 | 社群共识 | 管理员/成员互验 | 多人分包，集体任务，贡献度可视化 |
| **LBS探店** | 世界币 (L1) | 陌生人 | 平台托管 | AI+定位自动验 | 地理围栏，预付托管，抢单制 |

### 3.2 典型用户流程

#### 场景A: 朋友互助 (个人币)

```
发起方:
APP首页 → [+] → 填任务"帮带咖啡" → 选"个人币" → 填50 → @[小红] → 发布

接受方(小红):
收到Push → 查看 → [接受] → 买咖啡 → [完成] → 拍照上传

结算:
发起方收到通知 → [确认] → 50个人币自动转账

债务记录:
双方钱包显示"小红持有你的币50枚"
```

#### 场景B: 家庭教育 (团体币)

```
家长(管理员):
[团体]Tab → 进入"家庭" → [铸币] +300家庭币 → [发任务] "洗碗" 奖30币 → 指派给孩子

孩子:
[首页]看到任务 → [接受] → 洗碗 → 拍照上传 → 家长[确认] → 获得30家庭币

消费:
孩子进入[家庭商店] → 选"游戏时间1小时(60币)" → [购买] → 生成二维码 → 家长扫码核销
```

#### 场景C: LBS探店 (世界币)

```
发布者:
[广场] → [+] → 选"世界币" → 填"看X店排队情况" → 奖5Shell → 系统托管5币 → 发布(500m内可见)

执行者(附近陌生人):
地图上看到 → [抢单] → 到店拍照 → [提交] → AI识别有效 → 5Shell自动到账
```

## 4. 功能模块设计

### 4.1 任务 Tab (Task)

**定位**: 任务发现与管理中心，用户赚取货币的"工作inbox"

#### 4.1.1 双模式架构

**第一部分: 我的任务收件箱**
- 待决策 (Pending): 他人指派，需我决策(接受/拒绝/协商)
- 进行中 (Ongoing): 已承诺，正在执行子任务
- 已过期 (Expired): 超截止时间

**第二部分: 任务广场**
- 可抢单的公开任务
- LBS地理位置筛选
- 按距离/赏金/时间排序

#### 4.1.2 任务卡片要素

- 货币类型标识(💎/👤/👥) + 数量
- 发布者头像 + 关系标签(好友/家庭/社团/陌生人)
- 任务标题和描述
- 截止时间倒计时
- 操作区: [拒绝] [协商] [接受] 或 [继续执行]

#### 4.1.3 子任务工作流

**A. 顺序执行模式 (Sequential)**
- 必须按1→2→3→4→5线性完成
- UI: 垂直时间线，当前步骤展开，未来步骤锁定🔒
- 流转: 当前步骤验证通过后自动解锁下一步

**B. 自由执行模式 (Free)**
- 可任选子任务完成，无依赖
- UI: 上半部分焦点卡片 + 下半部分网格
- 交互: 点击网格卡片触发置顶动画

#### 4.1.4 凭证系统

**支持类型**:
- photo: 照片(带时间水印)
- location: GPS定位(地理围栏验证)
- text: 文字描述
- file: 文件附件
- signature: 电子签名

**验证方式**:
- AI自动验证(世界币): OCR识别、坐标比对
- 人工验证(个人/团体币): 发布者或管理员确认

#### 4.1.5 任务生命周期

```
待接受 (Open)
  ↓ 用户点击"接受"
进行中 (In Progress)
  ↓ 执行者上传证据 + 点击"完成"
待验证 (Pending Verification)
  ↓ 发布者验收 / 系统自动验收
  ├─ 通过 → 已结算 (Completed) → 货币自动转账
  └─ 拒绝 → 争议 (Disputed) → 进入仲裁流
```

### 4.2 商店 Tab (Store)

**定位**: 信用兑现所，将持有的货币兑换为实际商品/服务

#### 4.2.1 双模架构

**[发现商店]**:
- 浏览他人店铺
- 用已持有的币消费
- 货币快捷筛选

**[我的店铺]**:
- 管理商品、库存
- 订单兑付
- 数据看板

#### 4.2.2 发现商店功能

**货币快捷入口**:
- 顶部横向列表展示"我持有的货币"
- 点击筛选接受该货币的商店

**商店卡片**:
- 店名、店主信息
- 兑付率、响应时间
- 商品预览
- 评分和销量

**店内页**:
- 商品网格(瀑布流)
- 支持多币种价格展示
- 商品详情和兑换

#### 4.2.3 兑换流程

```
1. 用户确认兑换 → 扣除货币
2. 生成兑换码: QR Code + 8位数字验证码
3. 消息推送给店主: "您有新的兑换订单"
4. 店主扫码核销 → 确认兑付
5. 货币正式转入店主账户
6. 订单完成，双方评价
```

**兑付时效**: 店主需在24小时内处理，超时自动退款并扣分

#### 4.2.4 我的店铺管理

**商品上架**:
- 实物: 线下核销
- 虚拟: 自动发货
- 服务: 线下核销

**库存管理**:
- 有限库存或无限(-1)
- 库存预警

**订单中心**:
- 待兑付(扫码核销)
- 已兑付
- 已退款

**数据看板**:
- 今日访客
- 收入汇总(按币种)
- 货币健康度(发行vs兑付比率)

### 4.3 消息 Tab (Message)

**定位**: 通讯中心 + 社交关系管理

#### 4.3.1 消息分类

**[好友消息]**:
- 与好友的IM会话
- 支持发送任务卡片
- 支持发送个人币红包

**[商店消息]**:
- 交易通知中心
- 订单状态更新
- 兑付提醒
- 争议通知

#### 4.3.2 通讯录系统

**新的朋友**:
- 好友申请列表
- 接受/拒绝

**我的团队**:
- 已加入的团体
- 显示团体持币余额

**添加好友**:
- 搜索用户ID/昵称
- 扫码添加

**创建团队**:
- 发起新团体
- 设置名称、类型、加入方式

#### 4.3.3 全局添加入口

消息Tab右上角 **[+]** 按钮:
- 添加好友
- 创建/加入团队
- 扫一扫(二维码)
- 我的二维码(个人名片)

### 4.4 我的 Tab (Profile)

**定位**: 个人资产与身份管理中心

#### 4.4.1 资产钱包

**世界币 (Shell)**:
- 余额显示
- 充值入口
- 提现入口

**我发行的个人币**:
- 增发按钮
- 当前流通量
- 持有者列表

**我持有的他人币**:
- 各好友/团体的币余额列表
- 转账功能

#### 4.4.2 身份看板

- 信用分
- 技能徽章(NFT)
- 历史完成率
- 评价记录

#### 4.4.3 其他功能

- 店铺管理入口
- 账号安全设置
- 通知设置
- 隐私设置(个人币可见性)

## 5. UI设计规范

### 5.1 设计理念

DoForMe是一个轻娱乐社交/创意类app，面向年轻用户群体。设计风格应该：
- **活泼有趣** - 使用鲜艳的色彩和圆润的形状
- **现代时尚** - 采用当下流行的设计元素
- **易于使用** - 清晰的视觉层次和直观的交互
- **充满活力** - 通过色彩和动效传递能量感

### 5.2 配色方案

| 用途 | 颜色 | HEX | 使用场景 |
|------|------|-----|---------|
| 主色调 | 玫瑰红 | #E11D48 | 主要按钮、重要标签、品牌元素 |
| 次要色 | 粉红 | #FB7185 | 次要按钮、装饰元素、渐变 |
| 强调色 | 蓝色 | #2563EB | CTA按钮、链接、活跃状态 |
| 背景色 | 浅粉 | #FFF1F2 | 页面背景 |
| 文字色 | 深玫瑰 | #881337 | 主要文字 |
| 次要文字 | 灰色 | #64748B | 辅助信息 |
| 成功色 | 绿色 | #10B981 | 完成状态、成功提示 |
| 警告色 | 橙色 | #F59E0B | 警告信息 |

### 5.6 间距系统

- xs: 4px - 紧密元素间距
- sm: 8px - 小间距
- md: 16px - 标准间距
- lg: 24px - 大间距
- xl: 32px - 区块间距
- 2xl: 48px - 大区块间距

### 5.7 组件设计规范

#### 按钮

**主要按钮**:
- 背景: 主渐变
- 文字: 白色
- 圆角: 8px
- 高度: 44px
- 阴影: 轻阴影
- Hover: 加深阴影 + 轻微缩放(1.02)

**次要按钮**:
- 背景: 白色
- 文字: 主色调
- 边框: 1px 主色调
- 圆角: 8px
- 高度: 44px
- Hover: 背景变为主色调5%透明度

#### 卡片

- 背景: 白色
- 圆角: 16px
- 内边距: 16px
- 阴影: 轻阴影
- Hover: 中阴影 + 轻微上移(-2px)
- 过渡: 200ms ease

#### 输入框

- 背景: 白色
- 边框: 1px #E5E7EB
- 圆角: 8px
- 高度: 44px
- 内边距: 12px
- Focus: 边框变为主色调，带外发光

### 5.8 动效规范

**过渡时间**:
- 快速: 150ms - 小元素状态变化
- 标准: 200ms - 按钮、卡片hover
- 慢速: 300ms - 页面切换、模态框

**缓动函数**:
- ease-out: 元素进入
- ease-in: 元素退出
- ease-in-out: 状态变化

**常用动效**:
1. 按钮点击: 轻微缩放(0.98) + 阴影变化
2. 卡片hover: 上移(-2px) + 阴影加深
3. 页面切换: 淡入淡出 + 轻微位移
4. 加载动画: 旋转 + 渐变色变化

### 5.9 无障碍设计

1. **颜色对比度**: 所有文字与背景对比度 ≥ 4.5:1
2. **触摸目标**: 最小44x44px
3. **焦点状态**: 所有可交互元素有明显焦点样式
4. **语义化**: 使用正确的组件和属性

## 6. 数据模型设计

### 6.1 核心实体关系

#### 用户表 (User)

```typescript
interface User {
  user_id: string;              // 用户ID (PK)
  nickname: string;             // 昵称
  shell_balance: number;        // 世界币余额
  my_token_name: string;        // 个人币名称
  my_token_issued: number;      // 累计铸造量
  created_at: string;           // 注册时间
}
```

#### 货币持有表 (Holding)

```typescript
interface Holding {
  holding_id: string;           // 持有ID (PK)
  holder_id: string;            // 持有者ID (FK: User)
  currency_type: 'personal' | 'guild';  // 货币类型
  currency_key: string;         // user_id 或 guild_id
  amount: number;               // 持有数量
  updated_at: string;           // 更新时间
}
```

#### 团体表 (Guild)

```typescript
interface Guild {
  guild_id: string;             // 团体ID (PK)
  name: string;                 // 团体名称
  admin_id: string;             // 管理员ID (FK: User)
  type: string;                 // 团体类型
  treasury_shell: number;       // 世界币储备
  guild_token_issued: number;   // 团体币总发行量
  created_at: string;           // 创建时间
}
```

#### 任务表 (Task)

```typescript
interface Task {
  task_id: string;              // 任务ID (PK)
  creator_id: string;           // 发布者ID (FK: User)
```

#### 任务结算逻辑

```typescript
function settleTask(task_id: string): void {
  const task = Task.find(task_id);
  
  if (task.currency_type === 'shell') {
    // 释放托管资金
    releaseEscrow(task.escrow_id, task.executor_id);
  } else if (task.currency_type === 'personal') {
    // 转账个人币
    transfer(task.creator_id, task.executor_id, 'personal', task.creator_id, task.reward_amount);
  } else if (task.currency_type === 'guild') {
    // 转账团体币
    transferGuildToken(task.currency_guild_id, task.executor_id, task.reward_amount);
  }
  
  // 更新任务状态
  task.status = 'completed';
}
```

```typescript
  subscribe(key: string, callback: Function): void {
    if (!this.listeners.has(key)) {
      this.listeners.set(key, []);
    }
    this.listeners.get(key)?.push(callback);
```

## 8. 风控与合规

### 8.1 金融监管合规

#### 世界币合规定性

**法律定位**: 预付式消费积分，受《单用途商业预付卡管理办法》约束

**合规措施**:
- 充值上限: 单用户5000元
- 禁止用途: 不可用于赌博、博彩
- 提现重税: 20%手续费，鼓励内部流通
- 资金监管: 充值资金存入监管账户

#### 个人币/团体币合规定性

**法律定位**: 债权凭证或虚拟商品

**合规要求**:
- 禁止法币交易对显示(不显示"1小明币=0.1元")
- 不可主动"出售"个人币(防证券化)
- 明确告知用户: "该货币价值由发行人信用背书，平台不担保兑付"

### 8.2 平台风险防控

#### 防欺诈机制

**世界币任务**:
- 强制托管: 发布时冻结资金，防止发布者跑单
- AI验证: OCR识别、GPS定位验证
- 人工抽查: 首月100%人工复核，后续抽样

**个人币任务**:
- 单次赏金限制: 不超过历史发行量的10%
- 增发记录公开: 供市场参考
- 社交差评机制: 争议时曝光

**冷启动保护**:
- 新用户24小时内不能发布世界币任务
- 新用户首次任务需人工审核

#### 防通胀机制

**团体币预警**:
- 当M2增速超过储备增速时，向管理员推送通胀警告
- 国库可视化: 铸币总量 vs 已兑付量 vs 储备金

**个人币上限**:
- 建议设置软上限(如10000枚)
- 超限需解锁或提供兑付能力证明

#### 内容安全

**AI预审**:
- 任务描述敏感词过滤(色情、政治、暴力)
- 图片OCR识别(防二维码导流、防暴力内容)

**人工审核**:
- LBS任务人工抽查
- 高额世界币任务人工审核

### 8.3 争议仲裁流程

```
争议提起 → 双方举证(48小时) →
├─ 世界币任务: 平台AI+人工判定，输家扣除5%仲裁费
├─ 个人币任务: 社交曝光(差评标记)，无强制划转
└─ 团体币任务: 团体管理员二次判定，或成员投票(DAO模式)
```

**仲裁原则**:
- 证据优先: 照片、GPS、时间戳
- 快速响应: 48小时内完成
- 公平公正: 平台不偏袒任何一方

## 9. 商业模式

### 9.1 收入模式

#### 主要收入来源

- **国库 (Treasury)**: 团体的货币储备
